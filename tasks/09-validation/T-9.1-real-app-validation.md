# T-9.1 Проверка на реальном приложении

- **Этап:** Этап 9. Валидация перед 1.0.0
- **Тип:** задача
- **Спецификация:** §87 Phase 8
- **Отклонение от спецификации:** нет
- **Зависит от:** [T-8.6](../done/08-release/T-8.6-release-0-1-0.md)
- **Блокирует:** [T-9.2](T-9.2-api-stabilization.md)
- **Статус:** in_progress

## Что сделать

Long-lived потоки четырёх профилей (market-data busy loop, execution event loop, utility writer, background maintenance) на macOS Apple Silicon, Windows x64, Linux x86_64, Linux arm64; собрать feedback по mapping.

## Готово, когда

Есть отчёт по каждой платформе с наблюдаемым эффектом или его отсутствием.

## Результат

0.1.1 опубликован, зависимость T-8.6 снята. Добавлен
[воспроизводимый стенд](../../examples/validation/README.md) с четырьмя долгоживущими
потоками, baseline/QoS, ограниченными очередью/выборкой/временем ожидания,
проверкой ошибок и метриками throughput/p50/p99/drops. Локальный macOS arm64 прогон
успешен; Linux arm64 в Docker подтвердил переход в unsupported при EOPNOTSUPP
и отказ strict-сценария (ядро без CONFIG_UCLAMP_TASK). CI настроен на четыре платформы
с артефактами отчётов.

[Отчёт](../../docs/validation.md) разделяет подтверждённую интеграцию опубликованной версии,
локальные синтетические измерения и ещё не выполненные новые CI-прогоны.
До закрытия нужен выбор реального приложения, интеграция и feedback на всех четырёх платформах.
