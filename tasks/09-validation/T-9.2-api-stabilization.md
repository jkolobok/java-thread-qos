# T-9.2 Стабилизация API

- **Этап:** Этап 9. Валидация перед 1.0.0
- **Тип:** задача
- **Спецификация:** §3.2, §67
- **Отклонение от спецификации:** нет
- **Зависит от:** [T-9.1](T-9.1-real-app-validation.md)
- **Блокирует:** [T-9.3](T-9.3-release-1-0-0.md)
- **Статус:** in_progress

## Что сделать

Решить судьбу `current()` (§3.2), `trySet()` (D-02), состава `QosCapabilities`; при необходимости подключить japicmp.

## Готово, когда

Public API заморожен; CHANGELOG содержит breaking changes относительно 0.x.

## Результат

Подготовлен [кандидат API 1.0](../../docs/api-stability.md): оставить `trySet()` и текущие
восемь компонентов `QosCapabilities`, отложить неоднозначный portable `current()`.
Публичных breaking changes относительно опубликованного 0.1.1 сейчас нет.

Подключён `mvn -Papi-compat verify` (japicmp, baseline 0.1.1 из Central): несовместимые
изменения binary/source API в экспортируемом пакете ломают сборку. Профиль включён
в CI и проверку release-тега. Окончательная заморозка и CHANGELOG для 1.0 зависят
от реального feedback T-9.1; тикет остаётся открытым.
