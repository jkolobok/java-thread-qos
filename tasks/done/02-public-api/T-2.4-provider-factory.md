- **Отклонение от спецификации:** да, см. раздел «Отклонения» в индексе

- **Статус:** done

## Что сделать

- интерфейс §5;
- фабрика определяет ОС и архитектуру один раз по `os.name`/`os.arch` (нормализация `amd64`/`x86_64`, `aarch64`/`arm64`);
- provider хранится в holder-классе (class-init idiom), чтобы `set()` не брал monitor lock;
- фабрика принимает параметры через package-private конструктор для тестов.

## Готово, когда

Тест подставляет разные `os.name`/`os.arch` и получает ожидаемый provider без загрузки чужих native-символов.

## Результат

Интерфейс `ThreadQosProvider` (`set()` возвращает boolean «применено ли native», нужно для `trySet()`), `ThreadQosProviderFactory.create(osName, osArch)` с нормализацией `amd64/x86_64/x64`, `aarch64/arm64`; holder-идиома в `ThreadQos.Holder`. Тест подставляет 13 значений `os.name` и 12 `os.arch`; создание провайдера для чужой ОС не трогает native.
