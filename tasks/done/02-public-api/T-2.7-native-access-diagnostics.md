# T-2.7 Диагностика native access

- **Этап:** Этап 2. Публичный API и noop-провайдер
- **Тип:** задача
- **Спецификация:** §29, §31 (после правки D-08)
- **Отклонение от спецификации:** да, см. раздел «Отклонения» в индексе
- **Зависит от:** [D-08](../00-decisions/D-08-native-access-jdk25.md), [T-2.3](T-2.3-thread-qos-exception.md), [T-2.8](T-2.8-ffm-support.md)
- **Блокирует:** нет
- **Статус:** done

## Что сделать

В `FfmSupport` при первом обращении к нативному provider проверять `ThreadQos.class.getModule().isNativeAccessEnabled()`. Если `false`, сформировать подсказку из §31 (с реальным именем модуля и вариантом `ALL-UNNAMED`) и добавить её в сообщение любой `ThreadQosException`, возникшей при linkage. `IllegalCallerException` оборачивать с той же подсказкой.

## Готово, когда

Job из T-1.5 видит подсказку в сообщении.

## Результат

`FfmSupport.isNativeAccessEnabled()` / `nativeAccessHint()` / `nativeAccessHintText(Module)`; подсказка добавляется ко всем linkage-ошибкам через `FfmSupport.linkageFailure`. Подтверждено тестами профилей deny/warn.
