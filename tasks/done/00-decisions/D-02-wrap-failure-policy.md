## Что сделать

Спецификация не говорит, что делать, если `set()` внутри `wrap()` бросил `ThreadQosException`: поток умирает до запуска task.

Рекомендуемое решение:

- `wrap()` строгий: исключение пробрасывается, task не запускается;
- добавить `ThreadQos.trySet(QosClass): boolean`, который не бросает при native-ошибке и возвращает `false`, для тех, кому важнее запустить поток.

Выбор задокументировать явно.

## Готово, когда

Решение внесено в §23 и в публичный API §3.2.

## Результат

Выбран строгий `wrap()` + `trySet(QosClass): boolean`. Добавлен §23.1 и `trySet` в листинг §3.2.
