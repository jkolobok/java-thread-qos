# T-3.1 MacOsQosNative

- **Этап:** Этап 3. macOS
- **Тип:** задача
- **Спецификация:** §7.1–§7.4, §75
- **Отклонение от спецификации:** нет
- **Зависит от:** [T-2.8](../02-public-api/T-2.8-ffm-support.md)
- **Блокирует:** [T-3.2](T-3.2-macos-provider.md), [T-3.3](T-3.3-macos-readback.md)
- **Статус:** done

## Что сделать

- константы `QOS_CLASS_*` (0x21 / 0x19 / 0x15 / 0x11 / 0x09) с комментарием-ссылкой на `pthread/qos.h`;
- downcall `pthread_set_qos_class_self_np(int, int) -> int` через `defaultLookup()`;
- `relative_priority = 0`;
- handle создаётся один раз в holder-классе.

## Готово, когда

Symbol-resolution тест на macOS проходит (§53).

## Результат

`MacOsQosNative`: константы 0x21/0x19/0x15/0x11/0x09 (+ `QOS_CLASS_UNSPECIFIED`) сверены с `sys/qos.h` из Xcode SDK; downcall `pthread_set_qos_class_self_np(int,int)->int` через `defaultLookup()`, `relative_priority=0`. Handles линкуются один раз через `FfmSupport.Lazy` (holder-идиома заменена: статический инициализатор давал `ExceptionInInitializerError`/`NoClassDefFoundError` при отказе native access, что нарушает §77). Symbol-resolution тест проходит.
