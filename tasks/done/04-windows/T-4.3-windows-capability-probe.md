- **Этап:** Этап 4. Windows
- **Тип:** задача
- **Спецификация:** §8, §18, §21, D-06, D-07
- **Отклонение от спецификации:** да, см. раздел «Отклонения» в индексе
- **Зависит от:** [T-4.1](T-4.1-windows-native.md), [T-4.2](T-4.2-windows-throttling-layout.md), [D-06](../00-decisions/D-06-capabilities-shape.md)
- **Блокирует:** [T-4.4](T-4.4-windows-provider.md)
- **Статус:** done

## Что сделать

При инициализации provider вызвать `GetThreadInformation(ThreadPowerThrottling)` (read-only).

- `ERROR_INVALID_PARAMETER` / `ERROR_NOT_SUPPORTED` → `powerThrottlingSupported=false`, `unsupportedReason` заполнен, исключение не бросается;
- `priorityAdjustmentSupported=true` всегда;
- `qosSupported = priority || throttling`.

## Готово, когда

Unit-тест с подменённым результатом probe; integration test на `windows-latest` показывает `throttling=true`.

## Результат

Lazy probe через `FfmSupport.Lazy<State>`: `GetThreadInformation(ThreadPowerThrottling)`; любая ошибка (87/50/прочие) → `powerThrottlingSupported=false` + `unsupportedReason`, без исключения; `priorityAdjustmentSupported=true`; `qosSupported=true`. Linkage-ошибка → capabilities unsupported с текстом, `set()` бросает то же исключение. Unit-тест с фейком (`WindowsThreadQosProviderTest`) на каждый исход; integration-тест печатает capabilities и требует `throttling=true` только при `-Dthreadqos.requireSupported=true` (нельзя проверить локально, что server-SKU runner поддерживает throttling).
