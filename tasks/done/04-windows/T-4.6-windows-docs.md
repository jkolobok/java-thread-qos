## Что сделать

В README:

- HotSpot на Windows по умолчанию мапит Java-приоритет в `SetThreadPriority` при старте потока и при `Thread.setPriority()`, поэтому `DEFAULT` сбрасывает в `NORMAL`, а не в исходное;
- busy-spin поток на `THREAD_PRIORITY_HIGHEST` при насыщенном CPU может голодоморить GC/JIT-потоки;
- минимальные версии Windows (D-07).

## Готово, когда

Пункты есть в README-разделе «Windows».

## Результат

Раздел «Windows» в README: HotSpot сам вызывает `SetThreadPriority` (DEFAULT → NORMAL, а не исходное; `Thread.setPriority()` перекрывает), риск голодания GC/JIT при `HIGHEST`, минимальные версии (D-07), throttling ≠ affinity.
