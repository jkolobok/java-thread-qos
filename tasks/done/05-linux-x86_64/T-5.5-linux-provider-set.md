# T-5.5 LinuxThreadQosProvider.set()

- **Этап:** Этап 5. Linux x86_64
- **Тип:** задача
- **Спецификация:** §15, §15.1, §15.2, §16, §17
- **Отклонение от спецификации:** да, см. раздел «Отклонения» в индексе
- **Зависит от:** [T-5.4](T-5.4-linux-capability-probe.md), [D-04](../00-decisions/D-04-linux-rt-threads.md)
- **Блокирует:** [T-5.6](T-5.6-linux-integration-tests.md), [T-5.8](T-5.8-linux-docs.md)
- **Статус:** done

## Что сделать

Mapping §15.1 в record `LinuxUtilClamp(min, max)` и один `switch`.

Алгоритм:

1. `sched_getattr`;
2. если policy не в {`SCHED_OTHER`, `SCHED_BATCH`, `SCHED_IDLE`} → `ThreadQosException` (D-04);
3. в тот же attr записать `util_min` / `util_max`;
4. `sched_flags = existing | KEEP_POLICY | KEEP_PARAMS | UTIL_CLAMP_MIN | UTIL_CLAMP_MAX`;
5. `sched_setattr`.

Ошибка → `ThreadQosException(os=LINUX, nativeOperation="sched_setattr", errno)`. Affinity, nice, policy, cgroups не трогать.

## Готово, когда

Integration test §51 проходит и дополнительно проверяет, что `sched_policy` и `sched_nice` после `set()` не изменились.

## Результат

`LinuxUtilClamp.of(QosClass)` — единственный `switch`; алгоритм getattr → проверка policy ∈ {OTHER, BATCH, IDLE} (иначе `policyFailure`, D-04) → util_min/max → `flags |= KEEP_POLICY|KEEP_PARAMS|UTIL_CLAMP_MIN|UTIL_CLAMP_MAX` → setattr. Ошибка → `ThreadQosException(os=LINUX, "sched_setattr", errno + расшифровка)`. Integration-тест §51 проверяет util_min/max и неизменность policy/nice; выполняется только на ядре с uclamp (GitHub `ubuntu-24.04`), локально в Docker — skip с причиной.
