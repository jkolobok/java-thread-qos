## Что сделать

Отдельный workflow на tag `vX.Y.Z`: checkout → JDK 25 → `mvn verify` → sign → publish Central → GitHub Release (changelog, координаты, min Java, заметка про `--enable-native-access`, список ОС/архитектур, ссылка на Central).

Secrets доступны только этому job; forks их не получают. Guard от повторной публикации существующей версии (проверка наличия версии в Central перед deploy).

## Готово, когда

Тестовый прогон workflow на tag `v0.1.0-rc` проходит все шаги до publish.

## Результат

`.github/workflows/release.yml` на tag `v*`: environment `maven-central`, проверка tag == pom version,
guard от повторной публикации, `mvn -Prelease deploy` (для RC — `deploy -DskipUpload=true`,
сборка bundle без Central), SHA256SUMS, GitHub Release. RC 0.1.1 и final release успешны,
см. [отчёт](../../../docs/validation.md). Дополнительно workflow теперь требует полного
reusable CI на tagged commit, а Central guard разрешает только HTTP 404.
