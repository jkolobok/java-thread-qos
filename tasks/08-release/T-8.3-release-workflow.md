## Что сделать

Отдельный workflow на tag `vX.Y.Z`: checkout → JDK 25 → `mvn verify` → sign → publish Central → GitHub Release (changelog, координаты, min Java, заметка про `--enable-native-access`, список ОС/архитектур, ссылка на Central).

Secrets доступны только этому job; forks их не получают. Guard от повторной публикации существующей версии (проверка наличия версии в Central перед deploy).

## Готово, когда

Тестовый прогон workflow на tag `v0.1.0-rc` проходит все шаги до publish.

## Результат

`.github/workflows/release.yml` на tag `v*`: environment `maven-central`, проверка tag == pom version, guard от повторной публикации (HTTP-проверка repo1.maven.org), `mvn -Prelease deploy` (или `verify` для `-rc*` тегов — dry-run без Central), SHA256SUMS, GitHub Release (секция CHANGELOG, координаты, min Java, notice `--enable-native-access`, ОС/архитектуры, ссылка на Central, jars + .asc). Тестовый прогон на `v0.1.0-rc1` — после push и настройки secrets.
